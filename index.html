Connect your wallet on your computer

Read this first, because KwalaCoins works differently from most coins you may have seen: KWALA is its own blockchain, so its wallet is the KwalaCoins software itself — the node wallet you run on your own computer. It is not MetaMask, Phantom, or any browser / Web3 wallet, and you do not add it as a custom network in MetaMask. There is no website login that “connects” your wallet. You install the software, point it at your friend’s node, let it sync, then create the wallet inside it.

Use GitHub, not the old .zip. The .zip your friend first gave you is old and out of date. Everything below uses the current code at github.com/jkoncza/KwalaCoins — if a step, hash, or setting ever disagrees with that repo, the GitHub version wins.
  1. 1 Get the current software from GitHub. Go to github.com/jkoncza/KwalaCoins and either download the latest Release for your computer (Windows / Mac / Linux) or clone and build it from source using the build instructions in that repo. Do not install from the old .zip. When it’s installed you should have the wallet program (kwala-qt if you use the windowed version) and the command-line tools (kwalad and kwala-cli).
  2. 2 Tell it where your friend’s node is. KwalaCoins has no built-in seed list yet, so a fresh install knows nobody and will sit at 0 connections until you point it at a known peer. Your friend’s node is that peer. Add this one line — either in your kwala.conf file (in the KwalaCoins data folder the program creates on first run) or as a start-up option: 
    addnode=158.247.73.205:9777

    Starting from the command line instead? Use: kwala-qt -addnode=158.247.73.205:9777  ·  Port 9777 is the peer-to-peer port — that’s the one that has to match.

  3. 3 Start it and let it sync fully. Open the wallet / start the node and leave it running. It will download and check every block from the genesis block onward. On a chain this young that should not take long, but do not skip this — until it is fully synced, it cannot see coins sent to you and any balance it shows may be incomplete. In the windowed wallet, wait until the sync bar / tick says you are up to date. From the command line, check with: 
    kwala-cli getblockchaininfo
kwala-cli getpeerinfo
kwala-cli getconnectioncount
    You are connected properly when getconnectioncount is at least 1, getpeerinfo shows 158.247.73.205:9777, and in getblockchaininfo the blocks number has caught up with headers and verificationprogress is at (or very close to) 1.
  4. 4 Create your wallet — inside the program. If the windowed wallet asks you to create a wallet on first run, follow that prompt and give it a name you will recognise. From the command line: 
    kwala-cli createwallet "mywallet"
    Set a strong wallet passphrase if it offers one, and write it down offline. This wallet lives only on your computer — there is no company holding a copy for you.
  5. 5 Get your receiving address. 
    kwala-cli getnewaddress
    You will get an address starting with kwala1… (older-style addresses start with W… or K…). That kwala1… address is what you give your friend when he sends you KWALA. Only send KWALA to a KwalaCoins address — never to a Bitcoin or Ethereum address, even though the software looks similar to Bitcoin’s.
  6. 6 Check it worked. After your friend sends a test amount, keep your node running and synced, then check: 
    kwala-cli getbalance
kwala-cli validateaddress <your-address>
    Start with a small test send first. If the balance shows 0, the usual causes are: not fully synced yet (go back to step 3), 0 connections (re-check the addnode line and the 9777 port), or the coins were sent to a different address than the one this wallet controls.

Back it up — this is your money

Back up your wallet file (wallet.dat, in the wallet’s folder inside the KwalaCoins data folder) to a USB stick or another safe place that is not just the same computer, and keep your passphrase with it — separately.

If that file and passphrase are lost, the coins are gone. There is no password reset, no support desk, and no way for your friend to recover them for you.

Never share these

Never send anyone — not even someone claiming to help you “connect” or “verify” your wallet — any of these:

  • Your wallet.dat file
  • Your wallet passphrase
  • Any private key (kwala-cli dumpprivkey <address> — never run this for someone else)
  • Any seed / recovery words, if your wallet shows you any

Nobody legitimate ever needs them to send you coins. To receive KWALA, the only thing you ever give out is your public kwala1… address from step 5.

Explore the live chain from your own node

Once your node is synced (setup below), these are the explorer commands. They work today, against the real chain:

# Chain overview: height, best block hash, difficulty
kwala-cli getblockchaininfo

# Hash of the block at a given height, then the block itself
kwala-cli getblockhash 0
kwala-cli getblock <block-hash> 2

# A transaction, in decoded (readable) form
kwala-cli getrawtransaction <txid> true

# Is an address well-formed for this network?
kwala-cli validateaddress <address>

This page now browses live blocks directly from live.json, updated every 2 minutes by live_bridge.py running on a synced node — no Docker, no Esplora, no port-forward. That's item 3 on the listing readiness checklist — exchanges ask for a working public explorer by name. Address balances and old-transaction search still need a full electrs index; this bridge shows latest blocks and height.

Run a node & start mining

KwalaCoins has no DNS seeds, so a fresh node knows nobody. The GitHub README lists one public peer — connect to it explicitly, and your node finds the chain from there. More independent nodes is also the single biggest thing that makes the network look real to an exchange.

1 · Get the software

Clone and build from source, or grab the release, from the official repository:

git clone https://github.com/jkoncza/KwalaCoins

github.com/jkoncza/KwalaCoins — build instructions are in the repo, following the standard Bitcoin Core build for your platform.

2 · Connect to the network

Add the known peer to your kwala.conf, or pass it on the command line:

addnode=158.247.73.205:9777

P2P port 9777 · RPC port 9776. Let your node sync fully before mining or trusting its view of the chain.

3 · Get an address

KWALA addresses come in three formats. Bech32 is the modern default:

kwala-cli createwallet "mywallet"
kwala-cli getnewaddress

You'll get a kwala1… address. Legacy addresses start with W, script addresses with K. Back up your wallet file — lose it and the coins are gone; there is no recovery service.

4 · Mine

KWALA uses SHA-256d — the same algorithm as Bitcoin — so existing SHA-256 ASIC miners can point at this chain, and CPU/GPU mining is only realistic while the network is tiny.

Each block you find pays 100 KWALA. With one known peer and a days-old network, expect difficulty and hashrate to be very low — and to change fast as people join.

How to register it and put this site on it — step by step

  1. 1 Search the name at a registrar. Use a well-known registrar — for example Cloudflare Registrar, Porkbun, or Namecheap. Type in kwalacoins.org exactly. If it shows as available, note the first-year and renewal price before you pay — they are often different. Get the exact price quoted and approve it before anyone buys, because registrations are generally non-refundable.
  2. 2 Buy it in the right name, locked down. Register it under an account you and your friend control long-term (ideally the project’s own account, not a random helper’s). Turn on: two-factor authentication on the registrar account, WHOIS privacy (usually free), and auto-renew so the name can’t lapse. Skip the paid add-ons registrars upsell at checkout — you do not need them for this.
  3. 3 Host the website files for free. This site is plain HTML, so free website hosting is enough to start — GitHub Pages from the KwalaCoins GitHub project is the natural fit, and it is free. Publish the site files there first and confirm it loads on the temporary hosting address before touching DNS. Free hosting does not make the domain free — the domain is the yearly cost, hosting is $0.
  4. 4 Point the domain at the host. In your registrar’s DNS settings, add the records your host tells you to add — for GitHub Pages that means setting the custom domain (kwalacoins.org) in the repo’s Pages settings, adding a CNAME record for www pointing at the host address, and the host’s A / AAAA records for the bare domain. Copy the exact values from the host’s custom-domain instructions at the time — do not guess them.
  5. 5 Turn on HTTPS and wait for DNS. Once the records are in, enable “enforce HTTPS” in the host settings. DNS changes can take a few hours (occasionally up to 24–48) to spread — if the site does not load straight away, that wait is normal.
  6. 6 Add the explorer subdomain later. When a public node + explorer backend is running (see the checklist below), add an explorer DNS record pointing at that server, so the live explorer sits at explorer.kwalacoins.org and this website stays on the main domain.

Until those steps are done, share this preview and the GitHub repo — do not advertise kwalacoins.org as live, because it isn’t yet.

Getting listed on Kraken & Coinbase

The honest version first: nobody can put a coin on Kraken or Coinbase from the outside — not this page, not a paid "listing service." Both exchanges list assets only through their own application processes, both are free to apply to and merit-based, and both will currently say no to a days-old, single-peer chain. Here is exactly where KWALA stands and the path that changes that.

Watch out for scams: anyone who contacts the project offering a Kraken or Coinbase listing for a fee is fraudulent. Kraken states it never charges to evaluate or list an asset, and Coinbase's application is likewise free. Both exchanges only ever communicate through their official listing portals.

Listing readiness checklist

  • Open-source code, publicly availableDone — full source on GitHub, based on Bitcoin Core 28.0.
  • A public website with chain specificationsDone — this page. Next step is putting it on its own domain (see Get a domain below).
  • A real peer-to-peer networkNot done — no DNS seeds in the code and one known public peer. Exchanges need a resilient network they can run nodes against, not a single point of failure.
  • A live public block explorerLive — latest blocks & height via live.json, updated every 2–3 min from a synced node. Address / old-tx lookup still needs electrs.
  • Trading history, liquidity & a market makerNot done — KWALA has never traded anywhere, so it has no price, no volume, and no market depth. Major exchanges almost always come after a coin trades on smaller venues; both also assess market demand and community traction.
  • Legal & compliance groundworkNot done — both exchanges run legal review (including whether the asset could be a security) and compliance review. A named team, project documentation/whitepaper, and a legal opinion are the usual inputs.
  • Time on the clockThe chain launched 5 November 2026. Reviewers look for a network that has run stably, with real users, for far longer than a week.

Kraken — how it actually works

  1. Submit one listing application — one per asset, from the project team. Kraken explicitly says community members submitting duplicates hurts your chances.
  2. Evaluation against Kraken's legal, compliance, engineering, and business standards.
  3. Legal approval & integration prep — if approved, Kraken builds node/wallet support; this stage typically runs 2–6 weeks.
  4. Launch — announced only through Kraken's official listings channels.

Kraken never charges a fee to evaluate or list an asset.

Coinbase — how it actually works

  1. Apply on Coinbase's listings page — the questionnaire asks for a whitepaper, team background, tokenomics, source code links, and block explorer links.
  2. Business evaluation — market demand, community traction, and what integration would require. A brand-new chain (not one of Coinbase's supported networks) takes longer.
  3. Core reviews — legal, compliance, and technical security, all three mandatory.
  4. Approval & integration — approved assets become eligible to trade once Coinbase's technical integration is complete.

The application is free and merit-based; every asset is held to the same standards.

A realistic order of operations

  1. Grow the network: more public nodes, DNS seeds added to the code, and a hosted public explorer.
  2. Write it down: a short whitepaper and public team/project page — both applications ask for them.
  3. Trade somewhere first: smaller exchanges and aggregators (CoinGecko/CoinMarketCap listings included) build the price history and volume that Kraken and Coinbase evaluate.
  4. Then apply — once, properly, with everything above in hand.
